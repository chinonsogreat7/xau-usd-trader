# Offline paper execution

This is an **offline execution-engine demonstration**, not a connection to Exness.
It takes explicit synthetic quotes and trade instructions, then simulates position
sizing, entry fills, stop/target exits, modeled costs, account accounting, and risk
rejections. It cannot send a broker order.

The demonstration is not driven by our supply/demand candidate strategy. A separate
[strategy paper adapter](STRATEGY_PAPER.md) now performs that connection under a
strict, provisional synthetic-only timing contract. The scripted demonstration does
not implement every policy in `StrategySpec`, establish that the strategy is
profitable, or make the existing diagnostic baseline executable.

## Run the demonstration

From the project directory:

```sh
PYTHONPATH=src python3 -m xau_trader run-paper-demo
```

This prints a readable summary and creates a new report folder automatically.
On Mac, double-click **Run Paper Demo.command** for the same workflow. See
[the run guide](RUNNING_THE_BOT.md) for setup and the future MT5 deployment path.

For a specific report filename and machine-readable console output:

```sh
PYTHONPATH=src python3 -m xau_trader demo-paper-execution --report-json /tmp/xau-paper-report.json
```

Read the report to follow the simulated orders, positions, exits, costs, and risk
decisions. The quotes and trade instructions are deliberately constructed test
cases, not historical gold prices or signals generated by the strategy.

To inspect and change the scenario:

```sh
PYTHONPATH=src python3 -m xau_trader export-paper-scenario /tmp/xau-paper-scenario.json
PYTHONPATH=src python3 -m xau_trader simulate-paper /tmp/xau-paper-scenario.json --report-json /tmp/xau-paper-custom.json
```

All output paths must be new: these commands do not overwrite an existing file.
Choose another filename when repeating a command.

## What a scenario means

Both version 1 and version 2 JSON wrappers accept only `data_basis: "synthetic"`. Financial
decimal values, including prices and quantities, are decimal strings rather than
JSON floating-point numbers. The scenario must provide the complete explicit
policy; the exported example is the starting point for understanding its fields.
V2 additionally requires explicit daily loss-count and weekly drawdown thresholds.
V1 leaves these additional guards disabled; no thresholds are silently injected.
See [loss-limit configuration and semantics](LOSS_LIMITS.md).

Its instrument specifications, account balance, prices, costs, and risk controls
are **engineering fixtures**, not verified Exness specifications or a
recommendation for how much money to risk. Do not relabel a real MT5 export as
synthetic to feed it into this command.

## How to interpret execution

- An instruction is not a fill. Entry must respect its evidence-availability,
  entry-time, expiry, price, position-size, and account-risk checks.
- The first eligible quote is a single entry attempt. Rejection is final: there
  is no automatic retry, stacking positions, or same-quote re-entry after an exit.
- Buys use ask-side prices and sells use bid-side prices. Consequently, a long
  position is valued and closed on the bid side; a short uses the ask side.
- Protective stop and target levels are explicit instructions. This command does
  not discover the supply/demand strategy's structural stop or target for you.
- Position size must fit the configured risk and quantity limits. A quantity
  below the instrument minimum must not be rounded up to force a trade.
- Stop prices are not guaranteed fill prices. A quote that gaps through a stop
  can create a larger loss than the planned risk. Declared modeled costs also
  affect the result; this is not a complete model of broker execution.
- Missing or stale quotes are not executable prices. A safety halt cannot prove
  that a position was closed during a period with no usable quote. Check the
  reported position state and risk events rather than assuming a halt means flat.
- A quote-tick simulation does not establish available market depth, live latency,
  broker acceptance, real spread/slippage behavior, or financing charges.

Daily controls reset on UTC received-quote dates, using the first received equity
mark for that day; the overall drawdown halt remains latched for the run. These
are explicit simulator conventions. Configured v2 loss limits separately count total
net-losing closes by UTC exit day and track UTC-week equity drawdown; winners do not
reset the daily loss count. Financing uses a declared flat charge for each crossed
UTC date and is excluded from entry stop-risk/reward calculations. It is not an
Exness swap calculation. There is no persisted state across runs.

The report's `fingerprint` binds the whole report except that field itself;
`execution_fingerprint` binds the underlying kernel result. The embedded scenario
also records the exact input-byte hash and a canonical JSON hash. These hashes
detect changed artifacts; they do not verify that a supplied claim is true.

The existing candidate strategy proposes the immediate next M15 open and cancels
entries at declared closures. The importer can only observe the first supplied
tick in a candle, which may be later than that boundary. Connecting these paths
requires an explicit timing policy; this demonstration does not silently equate
those two times.

## What comes next

1. Extend and validate the [synthetic strategy adapter](STRATEGY_PAPER.md).
   It now connects recomputed structural plans to exact-boundary quote attempts,
   nearest-target reward/risk checks, sizing, and fills. Explicit provisional daily
   loss-count and weekly drawdown controls are now available. Their source approval,
   persistence, and a verified real-data execution contract remain pending.
2. Admit real quote data with verified symbol, contract, timezone, session, and
   cost evidence. Keep real-data evaluation separate from synthetic tests.
3. Build a demo-only MT5 connector with account checks, order-state reconciliation,
   duplicate protection, persistent risk state, and a tested emergency stop.

Logging into MT5 connects the terminal to the account; running these commands
does not connect this program. Keep Algo Trading disabled while using this
offline demonstration. See [the MT5 data-import guide](MT5_DATA_IMPORT.md) for
the separate historical-data workflow.
